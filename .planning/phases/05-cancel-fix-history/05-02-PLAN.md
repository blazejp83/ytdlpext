<task type="auto">
  <name>Task 1: Add cancel routing in service worker and fix history</name>
  <files>extension/service-worker.js</files>
  <action>
  **Cancel routing:**
  - In `chrome.runtime.onMessage.addListener`, add handler for `message.type === "cancelDownload"`:
    - Call `sendToHost({ type: "cancelAll" })`
    - Set `currentDownload = null` immediately (optimistic reset)
    - Call `resetDownloadBadge()`
    - `sendResponse({ ok: true })`
    - Return true for async

  - In `handleNativeMessage`, add handler for `msg.type === "cancelled"`:
    - Set `currentDownload = null`
    - `broadcastToPopup({ type: "downloadCancelled" })`
    - Call `resetDownloadBadge()`
    - Return

  **Fix history empty list bug:**
  The root cause: MV3 service worker can restart mid-download, losing the in-memory `currentDownload` object (which holds url and title). When the companion sends "complete", the handler spreads `...currentDownload` (which is null → empty object), so url/title are undefined in the history entry.

  Fix in the `msg.type === "complete"` handler:
  - When building the history entry, prefer companion-provided data over currentDownload:
    ```
    url: msg.data.url || currentDownload?.url || "",
    title: msg.data.title || currentDownload?.title || "",
    ```
  - This uses the new URL/Title fields from the companion's DownloadComplete message (Plan 01 adds these), falling back to currentDownload, falling back to empty string.
  - Also update the currentDownload spread to include url/title from msg.data:
    ```
    url: msg.data.url || currentDownload?.url || "",
    title: msg.data.title || currentDownload?.title || "",
    ```
  </action>
  <verify>Load extension in chrome://extensions — service worker registers without errors</verify>
  <done>Cancel messages route to companion, cancelled response resets state, history entries always have URL/title</done>
</task>
