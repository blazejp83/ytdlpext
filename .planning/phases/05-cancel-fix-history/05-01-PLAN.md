<task type="auto">
  <name>Task 1: Add cancel support with download tracking</name>
  <files>companion/messaging/types.go, companion/download/manager.go, companion/main.go</files>
  <action>
  **types.go:**
  - Add constants: `TypeCancelAll = "cancelAll"` and `TypeCancelled = "cancelled"`
  - Add struct: `CancelledResponse struct { DownloadID string json:"downloadId" }`

  **manager.go:**
  - Add fields to Manager: `mu sync.Mutex` and `active map[string]context.CancelFunc`
  - Initialize `active` map in `NewManager`
  - In `StartDownload`: create `ctx, cancel := context.WithCancel(context.Background())`, store `cancel` in `m.active[downloadID]` (under lock), pass `ctx` to `runDownload`
  - Change `runDownload` signature to accept `ctx context.Context` parameter
  - At start of `runDownload`: `defer func() { m.mu.Lock(); delete(m.active, downloadID); m.mu.Unlock() }()`
  - Change `cmd.Run(context.Background(), req.URL)` to `cmd.Run(ctx, req.URL)`
  - After the `cmd.Run` error check: detect `context.Canceled` — if `ctx.Err() == context.Canceled`, send `TypeCancelled` with `CancelledResponse{DownloadID: downloadID}` and return (instead of sending TypeError)
  - Add `CancelAll()` method: lock mutex, iterate `m.active`, call each cancel func, clear the map, unlock

  **main.go:**
  - Add case `messaging.TypeCancelAll` in `handleMessage` switch: call `manager.CancelAll()`, return nil
  </action>
  <verify>cd companion && go build ./...</verify>
  <done>Companion tracks active downloads, cancels them on cancelAll message, sends "cancelled" response per killed download</done>
</task>
