Root cause analysis:

1. go-ytdlp's `GetExtractedInfo()` requires `PrintJSON()` or `DumpJSON()` flag to work (documented in results.go:78-80). Without it, `checkJSON` is false on the stdout writer, JSON lines aren't parsed, and `GetExtractedInfo()` returns an empty slice.

2. The format query path (`handleGetFormats` in main.go) uses `.DumpJSON()` so `GetExtractedInfo()` works correctly there.

3. The download path (`runDownload` in manager.go) has NO JSON flag, so `GetExtractedInfo()` returns empty → `title = ""` and `filename = ""`.

4. `filepath.Base("")` returns `"."` — this becomes the DownloadComplete.Filename.

5. In the service worker complete handler, `msg.data.filename` = `"."` is truthy, so it overrides the real filename from progress updates. `msg.data.title` = `""` is falsy, so it correctly falls back to `currentDownload.title` (page title from content script).

Fix: Add `.PrintJSON()` to the download command. This maps to `--print-json` which outputs full JSON metadata to stdout after download completes. go-ytdlp already handles progress lines separately from JSON lines, so they coexist. Also add defensive guards for empty values.
</context>
