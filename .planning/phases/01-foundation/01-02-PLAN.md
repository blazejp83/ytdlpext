<task type="auto">
  <name>Task 1: Implement yt-dlp download handler in Go companion</name>
  <files>companion/download/manager.go, companion/main.go</files>
  <action>
  **download/manager.go** — Download manager using go-ytdlp:
  - `Manager` struct with a `messageWriter` callback `func(*messaging.Message)` for sending messages back to Chrome.
  - `StartDownload(req *messaging.DownloadRequest) error`:
    1. Generate a download ID (use a simple counter or UUID — `fmt.Sprintf("dl-%d", time.Now().UnixNano())` is sufficient).
    2. Create go-ytdlp command: `ytdlp.New()`.
    3. Set output template: `cmd.Output("%(title)s.%(ext)s")` for title-based filenames.
    4. Set output directory: `cmd.Paths(req.Directory)` or use `-P` flag equivalent.
    5. Set format: `cmd.FormatSort("res,ext:mp4:m4a")` + `cmd.Format("bv*+ba/b")` for best quality with muxing. This gets best video+audio merged, or best combined if separate streams unavailable.
    6. Register progress callback: `cmd.ProgressFunc(500*time.Millisecond, func(update ytdlp.ProgressUpdate) { ... })`. In the callback:
       - Build `ProgressUpdate` message with: DownloadID, Percentage from `update.Percent()`, Speed formatted as human-readable string (use `humanizeBytes(update.DownloadedBytes / elapsed)` or the pre-formatted string if available), ETA from `update.ETA().String()`, Filename from `update.Filename`.
       - Send via messageWriter callback.
    7. Run the command: `cmd.Run(context.Background(), req.URL)`.
    8. On success: send `Complete` message with DownloadID, Filename, full Path.
    9. On error: send `Error` message with DownloadID and error string. Parse common yt-dlp errors into user-friendly messages:
       - "is not a valid URL" → "Invalid URL"
       - "Unsupported URL" → "This site or URL is not supported by yt-dlp"
       - "ffmpeg" → "ffmpeg is required but not found. Install ffmpeg to enable video+audio merging."
       - "Sign in" / "age" → "This video requires authentication. Cookie support coming in a future update."
       - Default: pass through the yt-dlp error message.
  - Run downloads in a goroutine so the main message loop isn't blocked. The companion must continue handling ping/pong and new download requests while a download is in progress.

  **main.go** — Wire up download handler:
  - Create `download.Manager` with a messageWriter that calls `messaging.WriteMessage(os.Stdout, msg)`.
  - Add case for `TypeDownload` in the message router: unmarshal `DownloadRequest` from msg.Data, call `manager.StartDownload(req)`.
  - Add mutex or channel-based serialization for stdout writes (multiple goroutines may write progress simultaneously). Safest: use a channel that main loop reads from and writes to stdout sequentially.

  **Important**: go-ytdlp requires yt-dlp to be installed on the system. The companion should check for yt-dlp availability on startup and send a clear error message if not found. Do this with `exec.LookPath("yt-dlp")` in main.go init.
  </action>
  <verify>cd companion && go build ./... compiles. Manual test: build binary, pipe a download request message (with length prefix) to stdin, verify it attempts to run yt-dlp and sends progress/complete/error messages back on stdout.</verify>
  <done>Companion handles download requests via go-ytdlp, streams progress updates over native messaging, sends complete/error on finish, handles concurrent downloads safely, checks for yt-dlp availability on startup</done>
</task>

<task type="auto">
  <name>Task 2: Build download UI with progress and settings page</name>
  <files>extension/service-worker.js, extension/popup.html, extension/popup.js, extension/popup.css, extension/settings.html, extension/settings.js</files>
  <action>
  **service-worker.js** — Add download state management:
  - `let currentDownload = null;` — tracks active download state {id, url, title, status, percentage, speed, eta, filename}.
  - On receiving `progress` from native host: update `currentDownload` state. Broadcast to popup via `chrome.runtime.sendMessage({type: "downloadProgress", ...currentDownload})`. Catch error silently if popup is closed.
  - On receiving `complete` from native host: update `currentDownload.status = "complete"`. Broadcast to popup. Optionally reset after 5 seconds.
  - On receiving `error` from native host: update `currentDownload.status = "error"`. Broadcast to popup.
  - On `{type: "startDownload", url}` from popup:
    1. Get download directory from `chrome.storage.local.get("downloadDirectory")`. Default to `~/Downloads` if not set.
    2. Set `currentDownload = {id: null, url, title, status: "starting", ...}`.
    3. Send `{type: "download", url, directory}` to native host.
  - On `{type: "getDownloadState"}` from popup: respond with `currentDownload` (so popup can show progress if reopened mid-download).

  **popup.html** — Update with progress UI:
  - Add progress section (initially hidden): progress bar container (full-width bar with fill element), stats row (percentage text, speed text, ETA text), filename display.
  - Add status section: "Download complete!" with checkmark, or error message with retry button.
  - Add settings gear icon button in header that opens settings page.
  - Keep existing page-info and download-button sections.

  **popup.js** — Add download flow:
  - On DOMContentLoaded, also send `{type: "getDownloadState"}` to check for in-progress download. If active, show progress UI immediately.
  - Download button click: send `{type: "startDownload", url}`. Switch UI to progress state: hide download button, show progress section.
  - Listen for messages from service worker:
    - `downloadProgress`: Update progress bar width (`fill.style.width = percentage + "%"`), update percentage text, speed text, ETA text. Show filename when available.
    - `downloadComplete`: Hide progress section, show completion message with filename. Show "Download Another" button to reset.
    - `downloadError`: Hide progress section, show error message. Show "Retry" button.
  - Settings button click: `chrome.runtime.openOptionsPage()` or `window.open("settings.html")`.

  **popup.css** — Add progress styles:
  - Progress bar: Height ~8px, rounded, #e0e0e0 background. Fill: #4A90D9 blue, animated width transition (transition: width 0.3s ease).
  - Stats row: flexbox, space-between, small text (#666).
  - Completion state: Green checkmark (#4CAF50), centered text.
  - Error state: Red text (#D32F2F), retry button.
  - Settings gear: top-right corner, subtle icon button.
  - Smooth transitions between states (download button → progress → complete/error).

  **settings.html + settings.js** — Download directory configuration:
  - Simple page with: "Download Directory" label, text input for path, Save button, status message.
  - settings.js:
    - On load: read `chrome.storage.local.get("downloadDirectory")`, populate input. Show default placeholder "~/Downloads".
    - Save button: validate path is non-empty, save to `chrome.storage.local.set({downloadDirectory: value})`. Show "Saved!" confirmation that fades after 2 seconds.
  - Register as options page in manifest.json: add `"options_page": "settings.html"`.
  - Basic styling: same font/color scheme as popup, max-width 500px, centered.
  </action>
  <verify>Load updated extension. Open popup on YouTube — download button visible. Click download — progress bar appears and updates (requires companion to be running and connected). Open settings — can set download directory and save. Reopen popup — directory is persisted.</verify>
  <done>Popup shows real-time download progress (percentage bar, speed, ETA), handles completion and error states, settings page persists download directory to chrome.storage, UI transitions smoothly between idle/downloading/complete/error states</done>
</task>
