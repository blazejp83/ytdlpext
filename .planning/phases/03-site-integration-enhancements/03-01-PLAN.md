  **content.js changes:**
  After the existing IIFE, add a new IIFE for button injection. The injection code should:

  1. Define shared helpers:
     - `createButton(label, audioOnly)`: Creates a button element with class `ytdlext-dl-btn`, inline styles (no external CSS dependency — use `element.style` directly): small rounded pill, semi-transparent dark background (#1a1a1a, opacity 0.9), white text, 12px font, 6px 12px padding, pointer cursor, flex with gap for icon+text. Include an inline SVG download arrow icon (16x16). On hover: background lightens to #333.
     - `injectStyles()`: Inject a `<style>` tag once with `.ytdlext-dl-btn` hover state and transition.
     - On button click: call `chrome.runtime.sendMessage({type: "quickDownload", url: location.href, title: document.title, audioOnly: audioOnly})`.

  2. YouTube injection (`youtube.com`):
     - Target: `#owner` element (channel info row below video title). Insert button after the subscribe button area.
     - Use MutationObserver on `document.body` to wait for `#owner` to appear (YouTube loads dynamically).
     - Create button with `createButton("Download", false)`.
     - On `yt-navigate-finish` event: remove old button (if any) and re-observe for new `#owner`.
     - Guard: check `document.querySelector('.ytdlext-dl-btn')` before injecting to prevent duplicates.

  3. SoundCloud injection (`soundcloud.com`):
     - Target: `.soundActions` container on track pages (the row with like/repost/share buttons).
     - Use MutationObserver to wait for `.soundActions` to appear.
     - Create button with `createButton("Download", true)` (audio-primary, SITE-04).
     - Guard against duplicates.

  4. Bandcamp injection (`bandcamp.com`):
     - Target: The `.tralbumCommands` element on track/album pages (contains share/wishlist buttons).
     - If not found, try `.buyButtons` or `#trackInfoInner`.
     - Create button with `createButton("Download", true)` (audio-primary, SITE-04).
     - Guard against duplicates.

  5. Determine which site we're on from `location.hostname` and call the appropriate injector.

  **service-worker.js changes:**
  Add a new message handler for `"quickDownload"` in the `chrome.runtime.onMessage.addListener` callback:
  ```
  if (message.type === "quickDownload") {
    chrome.storage.local.get(["downloadDirectory", "fileExists"], (result) => {
      const directory = result.downloadDirectory || "~/Downloads";
      const fileExists = result.fileExists || "overwrite";
      currentDownload = {
        id: null,
        url: message.url,
        title: message.title || "",
        status: "starting",
        percentage: 0, speed: "", eta: "", filename: ""
      };
      const downloadData = {
        url: message.url,
        directory: directory,
        fileExists: fileExists,
        audioOnly: !!message.audioOnly
      };
      if (message.audioOnly) downloadData.audioFormat = "mp3";
      sendToHost({ type: "download", data: downloadData });
      sendResponse({ ok: true });
    });
    return true;
  }
  ```
  Also add `"DL..."` badge text on the tab during active download from quickDownload (set badge before sendToHost, clear on complete/error in handleNativeMessage).

  **manifest.json changes:**
  No changes needed — content.js already runs on all 5 sites via existing content_scripts config.
