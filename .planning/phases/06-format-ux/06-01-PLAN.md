<objective>
Cache format query results in the popup to avoid redundant companion round-trips on view switches, and remember the user's last chosen video resolution across sessions.

Purpose: Eliminate the 2-5 second format re-fetch when navigating History → back, and save users from reselecting their preferred resolution every time.
Output: Modified popup.js with in-memory format cache and chrome.storage.local resolution preference.
</objective>

<task type="auto">
  <name>Task 1: Cache format query results in popup</name>
  <files>extension/popup.js</files>
  <action>
Add a popup-scoped format cache variable at the top of the DOMContentLoaded callback:

- Add `let formatCache = null;` (stores `{ url: string, data: object }`)
- Modify `loadFormats()`: before sending `getFormats` message, check if `formatCache` exists and `formatCache.url === currentUrl`. If cache hit, call `populateFormats(formatCache.data)` directly, show the format picker, and return without fetching.
- On successful format fetch response (the callback inside `loadFormats()`), store `formatCache = { url: currentUrl, data: response }` before calling `populateFormats`.
- No explicit invalidation needed — popup context is destroyed on close, so cache is naturally cleared. The cache only helps within a single popup session (e.g., clicking History then Back).

Do NOT cache in chrome.storage or service worker — format data is large and stale quickly. A simple JS variable scoped to the popup lifetime is correct.
  </action>
  <verify>
Load extension, open popup on a YouTube video. Formats load (spinner visible). Click History, then click Back. Formats should appear instantly without the loading spinner. Verify in DevTools Network/Console that no second `getFormats` message is sent to the service worker on the back navigation.
  </verify>
  <done>Format cache hit skips companion round-trip; cache miss fetches normally; cache is URL-scoped so navigating to a different tab/page fetches fresh formats.</done>
</task>

<task type="auto">
  <name>Task 2: Remember last selected video format resolution</name>
  <files>extension/popup.js</files>
  <action>
Persist the user's last selected video resolution so it's preselected next time:

1. **Save on download**: In `videoDownloadBtn` click handler, after getting the selected radio value, extract the resolution text from the selected format row's `.format-label` span. Store it in chrome.storage.local as `lastVideoResolution` (e.g., "1920x1080"). Only store if a specific format was chosen (not "Best Quality" which has value "").

2. **Restore on format load**: At the end of `populateFormats()`, read `lastVideoResolution` from chrome.storage.local. If it exists, find the format row whose `.format-label` text matches the stored resolution. If found, check that row's radio button, add the `selected` class to that row, and remove `selected` from the "Best Quality" row. If not found (e.g., video only has 720p but user last picked 1080p), keep "Best Quality" selected — do nothing.

Match by resolution string (e.g., "1920x1080") rather than format ID, because format IDs vary across videos/sites while resolution strings are consistent.

Do NOT remember audio format selection — the audio chip default (MP3) is already sensible and rarely changed.
  </action>
  <verify>
Open popup on a YouTube video. Select 1080p format and download. Open popup again on a different YouTube video that also has 1080p — verify 1080p is preselected instead of "Best Quality". Open popup on a video that only has 720p max — verify "Best Quality" remains selected (graceful fallback). Clear chrome.storage.local `lastVideoResolution` and verify "Best Quality" is the default again.
  </verify>
  <done>Last chosen resolution persists in chrome.storage.local and is restored on next popup open when available; graceful fallback to "Best Quality" when resolution not available; only video resolution is persisted (not audio format).</done>
</task>
